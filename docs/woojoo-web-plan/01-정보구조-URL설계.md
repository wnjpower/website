# 01. 정보구조 · URL 설계

## 1. 설계 근거: 왜 "고객 유형별 분리"인가

영국 UK Electrical은 상단 내비게이션 첫 항목이 서비스가 아니라 **"Who We Help"** 이고, 그 아래가 Construction Companies / Interior Fit-Out Specialists / End Users 세 갈래입니다. 서비스(무엇을 하는가)가 아니라 **발주 주체(누가 발주하는가)** 로 1차 분기하는 구조입니다.

이 방식이 한국 전기내선공사 B2B에 특히 잘 맞는 이유:

- 전기공사는 **발주 주체에 따라 계약 형태·의사결정 기준·필요 서류가 완전히 다릅니다.** 종합건설사는 하도급 등록·시공능력평가액·보증을 보고, 인테리어 업체는 공정 속도와 협업 이력을 보고, 공장 시설담당자는 무정전 시공 가능 여부를 봅니다.
- AI가 답변을 만들 때 **질문에 발주 주체가 이미 포함**되어 있습니다("공장 증설할 전기업체", "인테리어 하는데 전기 협력업체"). 페이지가 주체별로 분리돼 있으면 매칭 정확도가 급상승합니다.
- 서비스 페이지만 있는 사이트는 "전기공사" 하나로 뭉뚱그려져 인용 대상이 되지 못합니다.

## 3. URL 규칙

| 규칙 | 내용 |
|---|---|
| 언어 | 영문 소문자 슬러그 (한글 URL 금지 — AI 크롤러·인용 시 URL 깨짐) |
| 구분자 | 하이픈(`-`) |
| 깊이 | 최대 3단계 |
| 후행 슬래시 | 통일 (있음으로 고정) |
| 파라미터 | 필터는 파라미터로, 인덱싱 제외(`?type=`) |
| 표준 | 모든 페이지 `canonical` 자기참조 필수 |

## 4. 내부링크 규칙 (AI 인용률에 직접 영향)

AI는 "이 페이지가 사이트 안에서 얼마나 중심적인가"를 내부링크로 판단합니다. 아래 3방향 링크를 **모든 페이지에 의무 적용**하세요.

### 4.1 3방향 링크 원칙

각 페이지는 반드시 아래 세 방향으로 링크를 가져야 합니다.

| 방향 | 예시 (전기내선공사 서비스 페이지 기준) |
|---|---|
| **상위** | `/services/` 허브 |
| **횡단(고객유형)** | `/clients/construction/`, `/clients/interior/` — "이 공사를 주로 의뢰하는 고객" |
| **하위(근거)** | 관련 `/projects/{slug}/` 2~3건 + 관련 `/faq/` 3문항 + 관련 `/guides/` 1건 |

### 4.2 교차 매트릭스

| 고객 유형 | 우선 연결 서비스 | 우선 연결 지역 |
|---|---|---|
| 종합건설사 | 전기내선공사, 분전반, 공장 동력 | 달성군, 북구 |
| 인테리어 시공사 | 회로증설, LED, 분전반 | 서구, 중구, 수성구 |
| 시설 관리자 | 공장 동력, 안전점검, 승압 | 달성군, 북구 |
| 건축주·자영업자 | 승압, 회로증설, LED | 서구, 달서구 |

## 5. 페이지 템플릿 구조 (공통 골격)

모든 하위 페이지는 아래 순서를 지킵니다. **순서 자체가 AI 인용 최적화 요소**입니다 — 결론이 위에 있어야 인용됩니다.

```
1. H1 (질문/니즈를 그대로 반영한 문장형 또는 명사구)
2. 요약 답변 블록 (3~4문장) ← ★ AI가 가장 많이 인용하는 구간
3. "이런 경우에 해당합니다" 체크리스트 (맥락 요소)
4. 본문 (H2 단위로 자기완결적 섹션)
5. 근거 블록 (법규 / 절차 / 소요기간 / 비용 구간)
6. 실제 시공사례 링크 2~3건
7. FAQ 3~5문항 (해당 페이지 전용)
8. CTA (견적 문의)
9. 관련 페이지 링크
```

### 요약 답변 블록 작성 규칙

```markdown
> **요약**
> [결론 문장]. [조건/범위 문장]. [행동 문장].
```

예시:
> **요약**
> 상가 계약전력을 5kW에서 20kW로 올리는 승압공사는 대구 기준 통상 2~3주가 소요됩니다. 한국전력 신청·수용가 설비 공사·한국전기안전공사 사용전점검 세 단계로 나뉘며, 이 중 한전 처리 기간이 가장 큰 변수입니다. 개업일이 정해져 있다면 최소 1개월 전에 착수하는 것이 안전합니다.

이 블록은 **앞뒤 문맥 없이 그대로 잘라도 완결된 답변**이어야 합니다. "위에서 설명한", "아래 표와 같이" 같은 표현을 넣으면 인용 가치가 사라집니다.

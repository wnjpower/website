## 설계 근거

UK Electrical의 케이스스터디는 극도로 짧습니다 — 고객명 + 관계 기간 + 제공 서비스 목록. B2B 신뢰 자산으로는 이것으로 충분하지만, **AI 인용 관점에서는 부족**합니다. AI가 인용하려면 "무엇이 문제였고, 어떻게 해결했고, 얼마나 걸렸는가"라는 서사가 필요합니다.

일본 阿部電気 방식(작은 실적이라도 구체적 수치와 함께 축적)과 결합해 아래 구조를 씁니다.

## 사례 작성 시 필수 규칙

### 1. 제목에 4요소를 넣으세요
`{지역} + {건물 유형} + {공사 항목} + {수치}`

- 좋은 예: "대구 달성군 물류창고 — 창고동 조명 320등 LED 교체, 야간 3일 시공"
- 나쁜 예: "○○ 물류센터 조명 공사"

앞의 제목은 "대구 창고 LED 교체 사례"라는 질문에 그대로 매칭됩니다.

### 2. 기간과 수치를 반드시 넣으세요
AI가 인용하는 것은 형용사가 아니라 숫자입니다. "빠르게 완료했습니다"는 인용되지 않고, "야간 3일, 총 18시간 작업"은 인용됩니다.

### 3. 고객명은 동의 없이 쓰지 마세요
동의를 받았다면 실명 표기가 신뢰도상 훨씬 강합니다. 동의가 없으면 "대구 서구 소재 40평 카페"처럼 **식별 불가능하되 구체적인** 표현을 쓰세요. "○○○ 고객님"보다 이쪽이 인용 가치가 높습니다.

### 4. 이미지 alt는 검색어처럼 쓰세요
- 나쁜 예: `alt="시공사진1"`
- 좋은 예: `alt="대구 서구 카페 분전반 신설 시공 완료 사진"`

### 5. 최소 축적 목표
| 시점 | 목표 사례 수 |
|---|---|
| 오픈 시 | 6건 (고객유형 4종 × 최소 1건씩 + 2건) |
| 6개월 | 15건 |
| 1년 | 30건 |

**중요**: 대형 현장만 올리려 하지 마세요. 일본 阿部電気 사례처럼 작은 현장이라도 꾸준히 축적한 사이트가 검색·인용에서 이깁니다. 콘센트 증설 한 건도 "달서구 미용실 드라이기 전용 회로 3구 증설, 반나절"로 쓰면 훌륭한 롱테일 자산입니다.

## 필터 설계

`/projects/` 허브에 아래 4축 필터를 두되, **필터 결과 URL은 인덱싱하지 마세요**(중복 콘텐츠). 대신 조합이 자주 검색되는 것만 정적 페이지로 별도 생성합니다.

| 축 | 값 |
|---|---|
| 고객 유형 | 건설사 / 인테리어 / 시설관리 / 건축주 |
| 공사 항목 | 8개 서비스 |
| 지역 | 5개 권역 |
| 규모 | 소규모 / 중규모 / 대규모 |

정적 생성 권장 조합 예시:
- `/projects/cafe/` — 카페·음식점 사례 모음
- `/projects/factory/` — 공장 사례 모음
- `/projects/led/` — LED 교체 사례 모음
